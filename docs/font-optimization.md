# 인생원작 공통 폰트 최적화

포털과 소설·오디오북·영상 리더가 동일한 `/fonts/` 자산을 사용한다. 기존 Hahmlet과 IBM Plex Sans KR의 글자 형태를 유지하고, 수정본의 내부 이름은 ToldLife Serif와 ToldLife UI로 바꿨다. 폰트 생성은 고정된 로컬 원본으로 수행하므로 빌드와 실제 화면에서 Google Fonts에 접속하지 않는다.

제목과 UI의 글자는 작은 공통 서브셋에 담고, 나머지 글자는 원본 전체 문자 범위를 중복 없이 나눠 필요할 때만 읽는다. 새 제목과 UI 문구는 빌드할 때 공통 서브셋에 반영된다. 명조 본문 400은 정적 글자 형태로 제공하고, 제목과 강조에 쓰는 500부터 800까지는 가변 굵기를 유지한다. 실제 600 굵기와 기존 제목 모양도 유지하면서 본문이 사용하지 않는 굵기 데이터를 함께 받는 낭비를 줄인다.

나머지 글자는 원고의 사용 빈도 순서로 묶는다. 자주 같이 읽는 글자가 여러 유니코드 순서 파일에 흩어져 큰 파일들을 함께 받는 일을 줄인다. 빈도는 분할 순서에만 사용하고 드문 글자를 제거하지 않는다. 글자 형태와 간격 데이터는 유지하며 웹용 출력에서는 픽셀 격자 보정용 힌팅 명령을 제외한다. 원고·오디오·자막은 생성이나 수정의 대상이 아니다.

원본 폰트와 라이선스는 패키지 밖의 `assets/fonts/sources`, 생성기는 `packages/reader-ui/src/fonts/reader-fonts.mjs`에 있다. 생성 자산은 `.deploy/reader-fonts`의 입력 해시별 캐시를 사용한다. 각 리더의 빌드 산출물에 같은 폰트 묶음을 담고, 최종 조립 단계에서 파일의 해시와 묶음의 일치를 검사한 뒤 최상위 `/fonts/`에 한 번만 배치한다.

소설은 저장한 서체·글자 크기·줄 간격을 첫 CSS 계산 전에 HTML 속성으로 복원한다. Vue의 설정 변경도 같은 속성을 갱신한다. 고딕을 저장한 독자의 본문은 서버의 기본 명조를 먼저 받은 뒤 고딕으로 바뀌지 않는다. 작품 홈은 공통 제목과 UI 600만 preload하며, 소설 읽기는 저장된 명조 400 또는 고딕 400과 UI 600을 골라 preload한다. 저장소가 막히거나 값이 잘못되면 기존 기본 설정인 20px·넓은 줄 간격·명조를 사용한다.

해시가 붙은 WOFF2와 CSS에는 1년 `immutable` 브라우저 캐시를 적용한다. manifest에는 `no-cache`를 적용하고 HTML의 기존 갱신 정책은 유지한다. 개발·독립 preview 서버도 같은 `/fonts/` 주소와 MIME 타입을 제공한다.

소설과 오디오북 탭은 각 리더의 기존 페이지로 이동한다. 이번 범위는 공통 폰트, 한글 서브셋, 선로딩과 캐시 최적화이며, 작품 상세를 단일 화면으로 통합하는 라우팅 변경은 별도 작업이다.

2026년 10월 11일 Chromium에서 기존 운영 화면과 로컬 조립 결과를 같은 화면 크기로 비교했다. 작품 상세 첫 진입의 폰트 요청은 32개에서 4개, 폰트 파일 전송은 425,110바이트에서 216,136바이트로 약 49.2% 줄었다. 폰트 CSS 원문은 약 465 KB에서 80 KB로 줄고 선언은 744개에서 220개가 됐다. 제목의 크기와 줄바꿈은 같았으며, 소설과 오디오북 왕복의 추가 폰트 전송은 0바이트였다. 시간 비교는 로컬과 운영의 네트워크 조건이 달라 제외했다. 저장소 검사, 워크스페이스 단위 검사, 세 리더의 빌드·typecheck·공유 메타데이터 검사, 두 작품의 주소와 캐시 브라우저 검사 16개를 통과했다. 오디오북과 영상 재생 검사도 통과했다. 소설 브라우저 검사에서는 초기화 전에 키보드 입력을 보내던 테스트를 실제 리더 준비 상태까지 기다리도록 보완하고 모든 기기에서 재검증했다. 독립 preview는 VitePress 1.x의 Polka 서버에 최상위 폰트 경로를 추가해 운영과 같은 URL을 제공한다.
