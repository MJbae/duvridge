# 듣는 자서전 제작 가이드

배병희 자전소설 『내 논을 파는 한이 있어도』를 어르신이 듣고 볼 수 있는 오디오북으로 만드는 작업이다. 회차마다 MP3(듣기용, 보통 배속), MP4(큰 자막 영상, 0.9배속), 각각의 SRT(자막)를 만든다. 만든 MP3는 [오디오 웹 앱](../../apps/toldlife-audiobooks/)에서 글과 함께 들을 수 있다. 새 세션은 이 문서와 연결된 모노레포 안내를 보고 이어서 작업한다.

이 제작 도구는 Duvridge 모노레포의 `tools/audiobook-production/`에 있다. 설치·검증·배포 정책은 [루트 README](../../README.md), 제작 도구의 경로와 보존 정책은 [오디오 제작 안내](../../docs/audio-production.md)를 따른다.

## 현재 상태 (2026-10-09 기준)

2026-10-09에 고친 원고와 삽화로 오디오북을 다시 만들기로 하고, 웹 앱에 있던 이전 원고의 녹음(프롤로그~3화)을 지웠다.

| 구분 | 회차 |
| --- | --- |
| 완료 | 프롤로그~23화, 에필로그, 외전 (26편, 웹 MP3 합계 약 75분) |

- **같은 날 원고가 바뀐 회차:** 바뀐 줄만 다시 녹음했다. 프롤로그는 원고를 한 번 더 고쳐 두 차례 만들었다. 2화는 문단 하나가 빠져 번호가 밀린 2줄을 다시 녹음했다.
- **호칭 변경:** "둘째 딸"을 "작은딸"로 바꿔(사용자 결정, 2026-10-09) 11화 3줄과 외전 1줄을 다시 녹음했다. 맏딸은 원고에 이미 "큰딸"로 적혀 있다.
- **이전 녹음 재사용:** 1~3화는 같은 자리의 문장이 그대로인 줄(1화 2줄, 2화 2줄, 3화 3줄)에 이전 원고의 녹음을 썼다.

**2화 연도 중복 수정 (2026-10-11):** 최신 정본에 맞춰 첫 문단의 "1940년대,"를 낭독 대본과 녹음에서도 제거했다. 시대·장소는 도입 메타데이터 "1940년대 · 안면도 중장리"에서 한 번만 읽고, 본문은 "태평양 전쟁과 광복을 전후해…"로 시작한다. 바뀐 첫 문단 1줄만 새로 녹음하고 나머지 8줄은 기존 클립을 재사용했다. 이전 첫 문단 클립도 보존하며, 웹 MP3·SRT와 장면 연결은 2화만 다시 반영했다. 영상 리더가 같은 낭독 문장을 사용하므로 2화의 0.9배속 MP4·SRT와 웹 영상 목록도 함께 갱신했다.

**기한:** Eleven v4 무료 체험은 **2026-10-22 무렵에 끝난다.** 전 회차 녹음은 그 전에 마쳤다. 원고를 고쳐 다시 녹음할 일이 그 뒤에 생기면 v4 요금과 이용 가능 여부부터 확인한다(아직 확인하지 않았다).

## 바로 시작하기

```bash
# 모노레포 루트에서
cd tools/audiobook-production
src/produce-audiobooks.sh                    # 26편 전부. 이미 만든 녹음은 캐시로 건너뛴다
src/produce-audiobooks.sh ep02 ep03          # 일부 회차만
```

- **이어서 하기:** 중간에 끊겨도 다시 실행하면 된다. 이미 만든 녹음은 다시 만들지 않는다.
- **시간 제한:** 한 회차는 몇 분 걸린다. 26편 전부면 1~2시간이라, Bash 기본 시간 제한(최대 10분)을 넘는다. 백그라운드로 돌리거나 몇 편씩 나눠 돌린다.
- **끝난 뒤:** 루트에서 `npm run narration:sync --workspace @duvridge/toldlife-audiobooks -- <회차>`로 웹 앱에 옮긴다. 받아쓰기 검수와 재녹음은 하지 않는다(아래 "사용자가 정한 것").

## 사용자가 정한 것 (바꾸지 말 것)

**받아쓰기 검수와 재녹음 금지 (사용자 결정, 2026-10-09):** 녹음을 받아쓰기(STT)로 검수하지 않고, 다시 녹음하지도 않는다. 받아쓰기가 정확하지 않아 검수 결과에 의미가 없다. 한 번 만든 녹음을 그대로 쓴다. 검수 목록을 만들거나 사용자에게 "들어 볼 줄"을 따로 보고하지 않는다.
- **다시 녹음하는 경우는 둘뿐이다:** 원고 문장이 바뀐 줄(캐시가 없어 자연히 새로 만든다), 그리고 사용자가 직접 듣고 고쳐 달라고 한 줄이다.
- **도구:** `generate_narration_clips.py`와 `produce-audiobooks.sh`는 기본으로 받아쓰기를 하지 않는다. 예전 검수 기능(`--stt`, `--retakes`, `--recheck`, `--approve`)과 `list_narration_review_items.py`는 남아 있지만 쓰지 않는다.

**목소리:** ElevenLabs **Eleven v4** 모델에 **Rei** 목소리(`nw7o9nqXCkQKoAs59z99`, 한국어·서울·노년 남성)를 쓴다. 사용자가 v2와 직접 비교해 듣고 "v4가 훨씬 낫다"고 골랐다.
- **모델:** 책 중간에 모델을 바꾸지 않는다. 바꾸면 목소리가 달라진다.
- **속도:** v4는 속도 설정을 받지 않는다. 그래서 조립할 때 속도를 정하고, 같은 녹음으로 두 가지를 만든다(사용자 결정, 2026-10-08).
  - **MP3(웹 사이트용):** 보통 배속(1.0). `output/<회차>.mp3`·`.srt`.
  - **MP4(통합 영상용):** `atempo=0.9`로 늦춘다. `output/video/<회차>.mp4`·`.srt`.
  - 쉼과 음악 길이는 두 속도가 같다. 낭독만 빠르거나 느리다.

**낭독 구성**
- **프롤로그:** 표지·회차 제목·시대 줄을 읽지 않고 본문 첫 문단 "믿었던 대형 곡물 상회가…"부터 시작한다(사용자 결정, 2026-10-10). 이 3줄은 대본에서 빼서 영상에도 나오지 않는다. 빠진 녹음은 `narration-clips/prolog/removed/`에 보관한다.
- **회차:** 회차 표시와 제목을 끊어 읽는다. "제일화. 어머니의 쇠갈고리." "일화"는 일화(逸話)로 들려서 "제○화"로 읽는다.
- **부 생략:** 1부, 2부 같은 부 구분은 화면과 낭독 모두에서 쓰지 않는다. 회차로 바로 시작한다.
- **숫자:** 읽는 말로 바꿔서 녹음한다(아래 "숫자 읽기"). 화면 자막에는 원고 표기(1936년 등)를 그대로 둔다.

**화면 (어르신용)**
- **표지:** 할아버지 수채화 초상(`content/books/bae-byunghee/public/images/bae-byunghee-hero-watercolor.png`, 모노레포 루트 기준) 위에 "내 논을 파는 한이 있어도", 그 아래 "배병희 자전소설"만 둔다. "듣는 자서전" 같은 문구는 넣지 않는다. 다만 프롤로그 영상에는 표지 화면이 나오지 않는다(2026-10-10, 본문부터 시작). 표지 화면 규칙은 `render_caption_frames.py`의 `cover` 종류에 남아 있다.
- **회차 화면:** 표지와 따로 넘어가는 화면이다. 작은 금색 회차 표시("프롤로그", "1화"), 금색 선, 큰 흰 제목, 시대·장소 순서로 놓는다. 시대·장소 줄 자리는 처음부터 비워 둬서, 그 줄이 나타날 때 제목이 움직이지 않게 한다.
- **자막 한 장 = 한 문장 전체:** 문장을 나눠 "갔다."처럼 꼬리만 따로 보이게 하지 않는다. 66자까지는 68px로 최대 3줄, 그보다 길면 60px로 최대 4줄로 둔다. 줄 길이를 고르게 나누고, "3억 원"처럼 수와 단위는 줄 사이에서 갈라지지 않게 한다.
- **자막 높이:** 줄 수와 관계없이 첫 줄은 늘 같은 높이(y=690)에서 시작한다. 자막이 1줄에서 3줄로 바뀌어도 시선이 크게 움직이지 않게 하려는 것이다.
- **삽화:** 원고의 `<!-- illustration: ep01-01 -->` 표시에서 바뀐다. 표시는 앞뒤 빈 줄이 있는 독립된 줄에 두고 다음 본문 문단 앞에 놓는다. `content/books/bae-byunghee/illustrations/manifest.json` version 2는 이미지 자산만 관리한다. 제작 시 표시의 현재 문단 위치를 계산하므로 본문을 윤문하거나 앞 문단을 추가해도 표시를 따라가며, 표시 자체는 자막·낭독·대본 줄에 들어가지 않는다.
  - 삽화 ID·파일명은 삽입 순서를 바꿔도 유지한다. 새 `ep01-03`을 `ep01-01`과 `ep01-02` 사이에 넣을 수 있다. 한 본문 문단 앞에는 표시를 하나만 두고, 표시 뒤에 본문 문단이 있어야 한다. 대표 삽화는 자산 목록의 `representative: true`로 회차 카드에만 선택하며 본문 위치를 강제하지 않는다.
  - 제작 영상은 본문 첫 표시 이전에 어두운 단색 배경을 사용한다. 자막·낭독·재생 길이는 유지한다. 실제 장면의 그림은 자산 목록에 등록된 최고 해상도 JPEG로 찾아 같은 이름의 과거 제작 원본이 잘못 들어가는 일을 막는다.

**소리**
- **음악:** 공유 콘텐츠의 회차 음악(`content/books/bae-byunghee/public/music/<회차>.mp3`)을 시작 4초 동안만 틀고, 낭독이 시작(4초)하기 전에 다 줄인다(2026-10-11, 음악이 끝나기 전에 낭독이 겹치던 문제). 끝에서 12초 다시 나온다. 읽는 동안에는 음악이 없다. 어르신이 말을 잘 알아듣게 하려는 것이다.
- **쉼:** 문단 사이는 0.9초, `* * *` 장면 전환은 2.2초, 회차 제목 뒤는 1.3~2초 쉰다.
- **음량:** -16 LUFS, 피크 -1.5 dBTP.

원본 자료는 [공유 책 콘텐츠](../../content/books/bae-byunghee/)에 있다. 원고 `manuscript.md`, 삽화, 음악을 **읽기만** 한다. 두 웹 서비스는 이 콘텐츠를 함께 사용한다. 제작 도구는 저장소 위치를 기준으로 경로를 찾으며, 별도 콘텐츠 사본을 시험할 때는 `MEMOIR_CONTENT_ROOT`에 그 절대 경로를 지정한다. 기존 녹음은 재생성 예정이므로 원고 편집을 제한하지 않는다. 새 녹음을 웹 앱으로 가져올 때 최신 원고와의 일치를 검증한다.

## 사전 조건

- **API 키:** 셸의 `ELEVENLABS_API_KEY`를 우선 사용한다. 없으면 이 제작 폴더의 `.env`에서 같은 이름의 키를 읽는다. 기존 키 파일을 사용할 때는 `ELEVENLABS_ENV_FILE`에 파일의 절대 경로를 지정한다. 키 파일을 저장소에 넣거나 키를 출력·로그로 남기지 않는다.
- **ElevenLabs 호출:** 기본값은 사용자 환경에 설치된 `~/.claude-work/skills/showreel/scripts/eleven.py`다. 다른 설치 경로는 `ELEVENLABS_SCRIPT`에 지정한다. 외부 helper와 키는 웹 빌드·CI에 필요하지 않다.
- **ffmpeg:** 이 Mac의 ffmpeg에는 `subtitles`, `drawtext` 필터(libass, freetype)가 없다. 그래서 자막은 Pillow로 그린 PNG를 이어 붙이는 방식이다. 글꼴은 Apple SD Gothic Neo(Bold index 6, Medium index 2)다.
- **Python:** numpy, Pillow가 있어야 한다. 스크립트는 `python3 -I`로 실행한다.

## 확인

1. **받아쓰기 검수 안 함 (사용자 결정, 2026-10-09):** 2026-10-08부터 줄마다 녹음을 받아쓰기해 원고와 비교했다. 그러나 받아쓰기가 고유명사와 옛말을 자주 잘못 적었다("배병희"를 "대병희", "김발"을 "긴 발"로 적는 식). 같은 녹음도 받아쓸 때마다 결과가 달랐다. 사용자가 "의미가 없다"며 검수와 재녹음을 모두 그만두게 했다.
   - **기록:** 2026-10-08에 사용자가 직접 들어 본 검수 실패 7줄(프롤로그 "독정", "곡물", 1화 "배병희는", "조새질", "소년은", 2화 "자염", "바닷일이")은 모두 발음이 맞았다. 자동 재녹음은 3번 → 1번 → 0번으로 줄였다가 2026-10-09에 검수와 함께 없앴다.
2. **고쳐 달라는 줄만 다시 만든다:** 사용자가 직접 듣고 틀렸다고 한 줄만 발음 표기를 바꿔 다시 만든다(예: "배병희는" → "배병히는"). `src/build_narration_script.py`의 `FIXED` 사전에 넣거나 대본 JSON의 `say`를 고친다. 그다음 `python3 -I src/generate_narration_clips.py narration-scripts/<회차>.json --only <줄> --force`, 이어서 `python3 -I src/assemble_audiobook.py narration-scripts/<회차>.json`을 실행한다.
3. **화면 확인:** 회차마다 2~3장을 뽑아 본다(`ffmpeg -ss <초> -i output/video/<회차>.mp4 -frames:v 1 x.png`). 표지, 회차 카드, 1줄·3줄 자막을 확인한다.

## 숫자 읽기 (`build_narration_script.py`)

**녹음할 때만 바꾸는 규칙**
- **연도:** 1936년 → 천구백삼십육년. 3남 2녀 → 삼남 이녀. 3억 → 삼억.
- **"일" 생략:** 1만 → 만, 1천 → 천.
- **분수:** 5분의 1만 → 오분의 일만. 분수를 먼저 처리해서 "만"을 단위로 착각하지 않게 한다.
- **달 이름:** 6월 → 유월, 10월 → 시월.
- **고유 표현:** 6·25 → 육이오.
- **고유어 수:** 5개 → 다섯 개.
- **한자 병기:** 녹음할 때 뺀다. 자염(煮鹽) → 자염. 일진월보(日進月步, 날마다…) → 일진월보, 날마다…. 화면 자막에는 원고 그대로 둔다.
- **단위로 처리하는 말:** 년대·년·월·부·화·억·만·천·원·남·녀·평·가구·세·대·호·번지·리·킬로·미터·%·마력·정보·도·일·볼트·톤·인·조·여.

**확인 결과:** 2026-10-08에 원고 26편 전체를 시험으로 돌려 봤다. 변환되지 않고 남은 숫자는 없었고, 낭독 분량은 37,316자였다. 원고에 숫자가 새로 들어오면 `build_narration_script.py` 실행 로그의 `[발음]` 줄을 확인한다.

**다시 확인 (2026-10-09, 고친 원고):** 남은 25편(1화~외전)의 낭독 분량은 25,687자다. 22화의 "500곳가량이"는 '곳'이 단위 목록에 없어 숫자로 남는다. 21화~외전의 RPC, 22화의 G마크, 23화의 GAP 같은 영문 약어도 그대로 남는다. 해당 회차를 녹음하기 전에 읽는 법을 정한다.

## 오디오 웹 앱

`apps/toldlife-audiobooks/`는 '읽으며 듣기'를 제공하는 독립 웹 서비스다. 원고·목차와 공통 읽기 UI는 모노레포의 공유 패키지에서 관리하고, 플레이어·낭독 문장 표시·자동 스크롤·다음 화 이어 듣기는 이 앱에서 유지한다. 지금은 2026-10-09 원고로 다시 만든 26편 전부를 연결했다.

- **실행:** 모노레포 루트에서 의존성을 설치한 뒤 `cd apps/toldlife-audiobooks && npm run dev`를 실행한다.
- **회차 추가:** 모노레포 루트에서 `npm run narration:sync --workspace @duvridge/toldlife-audiobooks -- ep04 ep05`를 실행한다. 제작 폴더의 `output/`에서 보통 배속 MP3와 SRT를 옮기면서, 문단 안 문장의 시작 시각을 실제 낭독의 쉼에 맞춘다(오디오북 SRT는 문단 안 문장 시각을 글자 수로 나눠 최대 1.7초 어긋난다). 원고에서 찾지 못한 문장이 있으면 옮기지 않는다.
- **테스트:** 웹 앱 폴더의 `npm test`(단위), `npx playwright test`(화면). 제작 파서는 루트의 `npm run test:production-parser`로 검증한다.
- **화면 동작:** 홈과 회차 화면 아래의 플레이어 막대 하나로 듣는다. 목차나 '이전 화 / 다음 화'로 회차를 옮기면 바로 들려 주고, 읽는 문장을 표시하며 화면이 따라간다. 회차 끝 음악이 끝나면 다음 화를 이어서 들려 준다. 사이트에 배경음악은 없다(회차 음악 파일은 제작용으로 남긴다). 자세한 내용은 [웹 앱 README](../../apps/toldlife-audiobooks/README.md)에 있다.
- **배포:** Duvridge의 [모노레포 CI/CD 정책](../../README.md)을 따른다. 공통 콘텐츠·UI 변경은 두 웹 서비스 모두 검증하며, 제작 도구·클립만의 변경은 웹 배포 범위를 넓히지 않는다. 반응 버튼은 웹소설 앱과 같은 Firebase를 쓰므로 반응 수가 합쳐진다(사용자 결정, 2026-10-08). 웹 빌드에 필요한 `VITE_FIREBASE_*` 4개 설정도 루트 배포 정책에서 관리한다.

## 주의할 점

- **공개 범위:** 낭독 음성(MP3)과 문장 시각은 공개해도 된다(사용자 결정, 2026-10-08). 영상(MP4)과 가족 재무 정보는 공개 저장소에 올리지 않는다.
- **녹음 파일 이름:** `narration-clips/<회차>/<줄번호>_<해시>.mp3`다. 해시는 낭독 문장, 목소리, 모델, 시드로 정해진다. 대본에 줄을 넣거나 빼면 줄번호가 밀려서 기존 녹음을 못 찾는다. 이때는 녹음 파일 이름과 `report.json`의 번호도 함께 옮긴다. 그러지 않으면 다시 녹음하느라 크레딧을 쓴다.
- **셸:** 기본 셸이 zsh라 `set -- $var`가 단어를 나누지 않는다. bash 스크립트는 `bash`로 실행한다. macOS의 bash 3에는 `declare -A`가 없다.
- **목소리 확인:** v4 생성 기록(history)에는 목소리 이름이 비어 나온다. 목소리를 바꿔 시험할 때는 음높이(`src/analyze_voice_pitch.py`)로 실제로 다른 목소리가 쓰였는지 확인한다.

## 남은 일

1. 원고를 고치면 고친 회차만 `src/produce-audiobooks.sh <회차…>`로 다시 만든다. 문장이 바뀐 줄만 새로 녹음되고 나머지는 캐시를 쓴다. 줄이 빠지거나 늘어 번호가 밀리면 그 뒤 줄도 새로 녹음된다.
2. 다시 만든 회차는 루트에서 `npm run narration:sync --workspace @duvridge/toldlife-audiobooks -- <회차>`로 옮긴다. 받아쓰기 검수와 재녹음은 하지 않는다.
3. 웹 배포 주소와 검증 결과는 [루트 README](../../README.md)에서 확인한다. 유튜브 일부 공개 재생목록으로 영상을 공유할지는 아직 정하지 않았다.
4. (선택) 할아버지나 고모님 반응을 받아 속도·자막 크기를 조정한다. 조정하면 `assemble_audiobook.py`만 다시 돌리면 된다(`--audio-tempo`, `--video-tempo`). 녹음은 다시 할 필요가 없다.
